# 幻想兽物语项目架构设计报告

## 一、项目概述
幻想兽物语是一款基于Unity引擎开发的多人在线角色扮演游戏，玩家可以选择不同的角色，收集宠物，与其他玩家合作或对战，完成各种任务和挑战。

## 二、目录结构设计

### 1. 核心目录结构
```
FantasyBeastStories/
├── Assets/
│   ├── Scripts/
│   │   ├── Application/       # 应用层 - 游戏管理和系统服务
│   │   ├── Domain/           # 领域层 - 核心业务逻辑和数据模型
│   │   └── Presentation/     # 表现层 - UI和用户交互
│   ├── Resources/            # 资源文件 - 配置表、预制体等
│   └── Scenes/               # 场景文件
└── Packages/                 # 第三方包和依赖
```

### 2. 各层职责详解

#### （1）Application层（应用层）
**职责**：负责游戏的全局管理、系统服务协调和跨领域逻辑处理

**主要文件**：
- `GameManager.cs`：游戏主管理器，负责场景切换、生成点管理、Boss死亡处理等全局逻辑
- `SaveManager.cs`：存档管理，处理游戏数据的保存和加载
- `AudioManager.cs`：音频管理，负责游戏中所有音效和音乐的播放
- `ExperienceManager.cs`：经验值管理，处理玩家升级和经验值计算
- `EnemiesGenorator.cs`：敌人生成器，根据游戏难度和波次生成敌人

**设计特点**：
- 使用单例模式确保全局唯一实例
- 通过ServiceLocator实现服务的注册和获取
- 处理跨领域的业务流程，如Boss死亡后返回大厅的流程

#### （2）Domain层（领域层）
**职责**：包含游戏的核心业务逻辑、数据模型和领域服务

**子模块详解**：

##### ① Audio模块
- 管理游戏中的音频配置和播放逻辑
- 核心文件：`AudioConfigSO.cs`、`SoundLibrarySO.cs`、`AudioType.cs`

##### ② CardData模块
- 管理游戏中的卡牌数据，包括不同品质的卡牌配置
- 核心文件：`CardConfigBase.cs`、`CardDatabasePublic.cs`、`CharacterCardType.cs`

##### ③ Character模块
- 管理玩家和宠物的属性、数据和行为
- **Attribute子模块**：定义角色属性系统，包括敌人和玩家的基础属性
  - 核心文件：`AttributeEnemyBase.cs`、`AttributePlayerBase.cs`、`PlayerAttributeConfigSO.cs`
- **Pets子模块**：定义宠物数据和行为
  - 核心文件：`PetData.cs`、`PetsBase.cs`、`Charmander.cs`
- **核心角色**：`PlayerController.cs`、`BingNv.cs`、`WizardBoy.cs`等

##### ④ Combat模块
- 管理战斗相关的逻辑和效果
- **FX子模块**：处理战斗特效，如 GuiLing 技能效果
  - 核心文件：`GuiLingBase.cs`、`ComponentFactory.cs`
- **Trigger子模块**：处理战斗中的触发逻辑，如攻击范围、碰撞检测等
  - 核心文件：`AttackRangeBase.cs`、`ColliderTriggerManager.cs`、`AutoAttackRange.cs`

##### ⑤ Data模块
- 定义游戏中的核心数据结构
- 核心文件：`AttackToken.cs`（攻击令牌）、`SaveData.cs`（存档数据）

##### ⑥ Enemy模块
- 管理敌人的行为和数据
- **Boss子模块**：定义Boss级敌人的配置和行为
  - 核心文件：`BossConfigSO.cs`、`Boss_Horror.cs`
- **核心敌人**：`EnemyBase.cs`、`EnemyData.cs`、`AttackableEnemy.cs`

**设计特点**：
- 使用状态机模式管理敌人行为（EnemyBase.cs中的状态切换）
- 基于SO（ScriptableObject）实现配置数据与逻辑分离
- 定义清晰的领域边界，各模块职责单一

#### （3）Presentation层（表现层）
**职责**：负责用户界面的展示和用户交互处理

**设计特点**：
- 使用MVC或MVVM模式分离UI逻辑和业务逻辑
- 基于Unity UI系统实现界面布局和交互

## 三、核心系统设计

### 1. 敌人系统设计

#### （1）敌人基类（EnemyBase.cs）
**核心功能**：
- 实现敌人的基本行为逻辑：Idle、Run、Attack、Die四种状态
- 使用状态机模式管理状态切换
- 处理敌人的AI逻辑，如追踪最近的玩家
- 管理敌人的属性和数据

**关键代码分析**：
```csharp
protected virtual void Update()
{
    if (GamePauseManager.isPaused || enemyData.currentState == EnemyState.Die)
        return;

    // 只有拥有者（Master Client）执行AI逻辑
    if (!EventChannelLocator.MainContainer.gameSettings.IsTest && !_network.IsMine)
        return;

    switch (enemyData.currentState)
    {
        case EnemyState.Idle: UpdateIdle(); break;
        case EnemyState.Run: UpdateRun(); break;
        case EnemyState.Attack: UpdateAttack(); break;
        case EnemyState.Die: UpdateDie(); break;
    }
}
```

**状态机工作流程**：
1. `TransitionToState()` 方法负责状态切换
2. 每个状态都有Enter、Update、Exit三个阶段
3. 通过动画控制器（Animator）同步角色动画

#### （2）敌人数据模型（EnemyData.cs）
**核心数据**：
- 敌人的基本属性：生命值、攻击力、防御力等
- 敌人的当前状态
- 敌人的初始化状态标记

**设计特点**：
- 使用AttributeEnemyBase封装敌人属性
- 与EnemyBase逻辑分离，便于数据持久化和序列化

### 2. 游戏管理系统（GameManager.cs）

#### （1）核心功能
- 游戏全局状态管理
- 生成点管理，为玩家和敌人提供生成位置
- Boss死亡后的流程处理
- 场景切换管理

#### （2）生成点管理
**设计思路**：
- 使用标签（Tag）查找所有生成点
- 维护生成点字典，便于快速查找
- 提供获取空闲生成点、根据玩家ID获取生成点等方法

**关键代码**：
```csharp
public GameObject GetEmptySpawnPoint()
{
    foreach (GameObject spawnPoint in spawnPoints)
    {
        if (spawnPoint == null) continue;
        ISpawnPoint sp = spawnPoint.GetComponent<ISpawnPoint>();
        if (sp != null && sp.IsEmpty())
        {
            return spawnPoint;
        }
    }
    return null;
}
```

#### （3）Boss死亡处理流程
**流程**：
1. 收到Boss死亡事件
2. 延迟10秒（让玩家观看死亡演出）
3. 自动保存游戏数据
4. 切换回大厅场景

**关键代码**：
```csharp
private IEnumerator DelayedLobbyTransition()
{
    yield return new WaitForSeconds(10f);
    if (SaveManager.Instance != null)
        SaveManager.Instance.SaveGame();
    SceneManager.LoadScene(1); // 加载大厅场景
}
```

### 3. 存档系统（SaveManager.cs）

**核心功能**：
- 游戏数据的保存和加载
- 使用加密算法保护存档数据
- 支持自动保存和手动保存

**设计特点**：
- 使用FileDataHandler处理文件读写
- 支持多个存档槽位
- 自动保存关键游戏状态（如Boss死亡后）

## 四、设计模式应用

### 1. 单例模式
**应用场景**：
- GameManager、SaveManager、AudioManager等全局管理器
- 确保全局唯一实例，方便跨场景访问

**实现方式**：
```csharp
public static GameManager instance;
void Awake()
{
    if (instance == null)
    {
        instance = this;
        DontDestroyOnLoad(gameObject);
    }
    else
    {
        Destroy(gameObject);
    }
}
```

### 2. 状态机模式
**应用场景**：
- 敌人行为管理（EnemyBase.cs）
- 玩家状态管理

**设计优势**：
- 清晰分离不同状态的行为逻辑
- 便于扩展新的状态
- 状态切换逻辑集中管理

### 3. 服务定位器模式
**应用场景**：
- ServiceLocator和DomainServiceLocator
- 实现服务的注册和获取，降低模块间耦合

**设计优势**：
- 解耦服务使用者和服务实现
- 便于单元测试和模拟
- 提高代码的可维护性

### 4. 观察者模式
**应用场景**：
- 事件系统（EventChannel）
- 如Boss死亡事件、游戏动作事件等

**设计优势**：
- 解耦事件发布者和订阅者
- 支持多对多的事件通知
- 提高系统的灵活性和扩展性

## 六、代码质量与可维护性

### 1. 代码规范
- 遵循C#编码规范
- 使用清晰的命名约定，如帕斯卡命名法（PascalCase）用于类和方法
- 使用XML注释说明类和方法的功能

### 2. 可维护性设计
- 模块化设计，每个模块职责单一
- 依赖注入降低模块间耦合
- 使用ScriptableObject分离配置数据和逻辑

### 3. 性能优化
- 对象池技术复用敌人和特效对象
- 避免每帧调用FindGameObjectsWithTag等昂贵操作
- 使用对象缓存减少GC开销

## 八、总结

幻想兽物语项目采用了分层架构设计，清晰分离了应用层、领域层和表现层，各层职责明确，耦合度低。通过使用多种设计模式，如单例模式、状态机模式、服务定位器模式等，提高了代码的可维护性和扩展性。

项目的核心特点包括：
1. 基于Unity引擎的组件化开发
2. 清晰的领域模型和业务逻辑分离
3. 完善的游戏系统，包括敌人系统、存档系统、经验值系统等
4. 多人在线支持，使用Photon网络框架
5. 良好的代码质量和可维护性设计

这种架构设计使得项目能够快速迭代和扩展，为后续的功能开发和性能优化奠定了坚实的基础。
